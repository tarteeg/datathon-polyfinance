# Better Auth implementation plan

Goal: connect the existing V1 forms to email/password authentication using the user's selected Next.js + Aurora PostgreSQL architecture.

Design: Better Auth owns credentials, sessions, and its schema through a small pg pool. The existing dashboard shell receives only the authenticated user's display fields. A Next.js proxy validates sessions for dashboard, chat, and mail requests; a server-only session helper is available to protected server code. Credentials live in ignored environment files. TLS verifies Aurora's certificate using the AWS RDS CA bundle supplied through configuration.

Tradeoffs: no ORM, Google OAuth, verification email, password reset, AWS deployment, or live database changes in this step. Amplify compatibility and deployed network access remain unresolved. Existing demo screens are retained.

1. Add the auth server/client, route handler, environment template, and CLI migration commands. Review against the installed Better Auth API.
2. Wire V1 forms with input validation, errors, pending states, and success navigation; remove password-displaying demo handlers. Add real identity and logout.
3. Protect dashboard/chat/mail requests and document mandatory authorization at future data/API boundaries.
4. Review the diff and references. Per AGENTS.md, do not run build, lint, or other validation commands unless explicitly requested. Live verification needs configured Aurora credentials and schema migration.

Runtime acceptance checks (pending authorization/configuration): register, invalid login, valid login, remember-me, reload/session persistence, logout, expired/revoked/forged cookie redirects, unauthenticated nested dashboard/chat/mail access, database unavailable, and TLS failure.
